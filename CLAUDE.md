# FullTiltPinball-Native: project notes

Native (SDL2) Space Cadet, Dragon's Keep and Skulduggery from Full Tilt! Pinball, built on the
SpaceCadetPinball decompilation; the remote `upstream` is k4zmu2a/SpaceCadetPinball, and the port is
built on its history.

Documentation: [README.md](README.md) (use, data layout, limitations),
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (how the engine is extended),
[docs/TESTING.md](docs/TESTING.md) (checks), [docs/REVERSE_ENGINEERING.md](docs/REVERSE_ENGINEERING.md)
(tools and measured facts).

## Rules for this repo

- Never put game data, the original `.EXE`s, Ghidra exports, decompiled listings or game text (table
  messages, mission texts) into tracked files. `re/work/` is git-ignored and is the only place for
  them. Test scripts match text by code and string id, never by the text.
- Your own Full Tilt! install (`$FULLTILT_DIR`) is read only (tables in `CADET/`, `DRAGON/`,
  `PIRATE/`; some installs also have `PIRATES/`, an identical copy of `PIRATE/`). Work on copies in
  `re/work/` (`re/work/game/`, re/test/README.md).
- Space Cadet keeps upstream's behaviour. Gate every Full Tilt behaviour that could change it with
  `pb::IsFullTiltTable()` (Dragon's Keep and Skulduggery only), never with `pb::FullTiltMode`,
  which is also true for Full Tilt's `CADET.DAT`. Changes that reach Space Cadet are listed in
  docs/ARCHITECTURE.md and are checked with the Space Cadet baseline comparisons in docs/TESTING.md.
- C++11 only (`CMAKE_CXX_STANDARD 11`): the Raspberry Pi build uses GCC 8.3.
- Shared resources have one owner at a time: each Xvfb display (`:90`-`:139`), the Wine prefix
  `re/work/wine-prefix` (use a private `cp -a` copy for parallel Wine runs), each build directory,
  the Ghidra project `re/work/ghidra-proj`. Test runs never use the user's desktop.
- Large temporary files go under `re/work/`, not `/tmp`.
- Machine-specific agent rules (local paths, checks before builds) go in the git-ignored
  `CLAUDE.local.md`.
- Documentation describes the project as it is (what, how to build, run, test, how it works,
  limitations). It is not a log: no history, dates of changes, task or review identifiers.

## Layout

| Path | Contents |
|---|---|
| `SpaceCadetPinball/` | Engine; Space Cadet rules in `control.cpp`; port modules `tables.*` (catalogue, gate), `table_text.*` (EXE text reader), `table_rules.h`, `ft_rand.*`, `ft_test_hook.*`, the new part classes |
| `SpaceCadetPinball/rules/` | Dragon's Keep (`dragon_*`) and Skulduggery (`pirates_*`) rules, shared `ft_common.*`; `*_tables.cpp` are generated by `re/rules_tables_gen.py` |
| `re/` | Reverse-engineering tools; `re/ghidra_scripts/`; `re/work/` (ignored workspace) |
| `re/test/` | Wine harness (`harness.py`, `ftharness/`, `scripts/`), hook runner (`hookrun.py`), hook scripts (`hook_scripts/`, `hook/<table>/<area>/`), standalone checks (`native/`), self-tests |
| `Platform/Windows/` | `build-mingw.sh`: Windows cross-build (deps + build); with `mingwcc.cmake` (toolchain) |
| `Libs/`, `build-win/`, `bin-win/` | Ignored: downloaded SDL2/SDL2_mixer MinGW libraries, Windows build tree, Windows output (`.exe` + 2 DLLs) |
| `docs/` | Project documentation |

## Build

    cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j        # bin/SpaceCadetPinball
    cmake -S . -B build-hook -DCMAKE_BUILD_TYPE=Release -DFT_TEST_HOOK=ON \
          -DFT_OUTPUT_DIR=$PWD/build-hook/bin && cmake --build build-hook -j       # test hook build

    Platform/Windows/build-mingw.sh                 # Windows: SDL libs into Libs/ (pinned, SHA-256), bin-win/*.exe

Run a table with `bin/SpaceCadetPinball -table=cadet|dragon|pirates` from a directory that holds the
table folder (README.md, Game data).

## Test

- Hook script: `python re/test/hookrun.py run --table <t> --bin build-hook/bin/SpaceCadetPinball
  --display <N> --out <dir> <script.uh>`; twice plus `hookrun.py compare <a> <b>` for
  repeatability. Format: re/test/hook_scripts/README.md.
- Wine vs native: `python re/test/harness.py run wine-<t>|native-<t> <script.json> --display <N>
  --out <dir>`, `harness.py compare`, `scripts/probe_run.py`, `hookrun.py compare-wine` /
  `rest-state`. Setup and details: re/test/README.md.
- Windows build under Wine: docs/TESTING.md (Windows build under Wine). Needs a private prefix and
  its own Xvfb display, never `re/work/wine-prefix`.
- Which checks to run for which change, and what each shows: docs/TESTING.md.

## Reverse-engineering setup

- `re/work/.venv`: Python with capstone and pefile (`re/work/.venv/bin/python re/<tool>.py ...`).
- Ghidra 12.1.2 in `$GHIDRA_INSTALL_DIR`. Headless export:
  `"$GHIDRA_INSTALL_DIR"/support/analyzeHeadless re/work/ghidra-proj fulltilt -import re/work/bin/<EXE> -scriptPath re/ghidra_scripts -postScript ExportAll.java re/work/export`.
  Ghidra refuses project paths that contain a folder starting with `.`.
- Tool list: docs/REVERSE_ENGINEERING.md.

## Key facts (verified)

- CADET.EXE, DRAGON.EXE and PIRATES.EXE are one PE32 engine build; 70-73 % of their code is
  identical. Each has its own table-rules module (Space Cadet's is upstream's `control.cpp`).
- The part-construction switch is identical in CADET.EXE and DRAGON.EXE: part types 1034-1038, 1042,
  1043 and several flippers per side are Full Tilt engine features that upstream (based on XP's
  `pinball.exe`) lacks. They are engine classes, not table-specific code.
- CADET.EXE itself has the Full Tilt engine behaviour where upstream differs (tilt timeout 15 s,
  plunger release boost 0.2 s, ...); Space Cadet in this port keeps upstream's except for the items
  in docs/ARCHITECTURE.md.
- The originals use the MSVC `rand()` generator from state 1, never reseeded; engine and rules share
  it (`ft_rand`).
- The originals step physics in about 1-2 ms from an uncapped loop; the port slices each frame into
  steps of at most 1 ms (not in hook runs).
- Dragon's Keep and Skulduggery read their strings from their own `.EXE` at run time; the `.EXE` must
  sit next to the `.DAT`.
- The Windows build compiles the same sources (only upstream's `_WIN32` branches differ); it keeps settings in `%APPDATA%\SpaceCadetPinball\imgui_pb.ini` and its table
  search list has no `/usr` entries. Its music has no fluidsynth (Timidity, then Windows' MIDI).
- All options, including `Music` (off by default), are shared by the three tables in
  `~/.local/share/SpaceCadetPinball/imgui_pb.ini`; high scores are per table (`DragonsKeep.` /
  `Skulduggery.` key prefixes, Space Cadet unprefixed).
- Music (Linux builds with fluidsynth's development files): one fluidsynth synthesizer for the whole
  process, created in `midi::music_init`, rendering through `Mix_HookMusic` (`music_fluidsynth.*`);
  tracks are cached MIDI bytes and every play gets a new player, so a track always starts at its
  beginning. SDL_mixer's own fluidsynth backend makes one synthesizer (with its own SoundFont
  presets) per loaded track and, with SDL_mixer < 2.8.1 / fluidsynth 1.x (the Pi), does not rewind a
  replayed track (stale position, or a voice-warning flood after a loop). Builds without
  fluidsynth (Windows) still use SDL_mixer. Check: `re/test/music_check.py` (docs/TESTING.md).
